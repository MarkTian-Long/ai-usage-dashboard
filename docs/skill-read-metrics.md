# Skill 说明读取统计

这是可观测代理指标：日志中出现了可识别的 `SKILL.md` 读取命令。它不证明 Skill 被完整加载、实际应用、调用成功或任务成功，也不检查工具输出中的读取成功与失败。不可作为调用次数、成功率或 Skill 质量排名。

## 数据与统计单位

- 只读枚举 `SourceRoot/sessions/`、`SourceRoot/archived_sessions/` 的 JSONL，沿用原生成器及按文件长度、修改时间复用的增量缓存。事件读取函数的指纹也须一致；仅修改汇总或页面不会使读取缓存失效。
- 只处理 `response_item` 的 `function_call` / `custom_tool_call`。可用清单、用户或助手名称提及、工具输出和 `event_msg` 内的普通文本不参与识别。
- 从 `session_meta` 继承会话；从 `turn_context`、`task_started` 或调用自身的 `turn_id` 关联轮次。缺少会话或轮次的调用不推测归属。完成或中止后清除当前轮次。
- `parent_thread_id`、`source.subagent`、guardian/subagent 来源及非根 `agent_path` 标记的文件不产生 Skill 统计；排除仅影响 Skill，不改变既有 Token/请求统计。迟到的子代理元数据也排除该文件的 Skill 事件。未留下这些元数据的旧日志无法可靠识别代理身份。
- 读取轮次在各自窗口内按 `session_id + turn_id + 来源 + Skill` 全局去重，跨活动/归档文件也只计一次。同一轮跨越窗口起点再次读取，只要窗口内有读取，该窗口计一次；近 7 天与近 30 天的计数不相加。
- 涉及任务数按不同主会话计。同一会话多轮读取同一 Skill 增加轮次，不增加任务数；不同来源的同名 Skill 分开统计，同来源同名视为同一 Skill，插件名称加入包名前缀，版本升级不拆分。
- 时间统一转换到 `Asia/Shanghai`（UTC+08:00）。近 7 天为截至日及前 6 个自然日，近 30 天为截至日及前 29 个自然日；本月从月初开始。另可选择全部观测历史或自定义日期。当天是截至刷新时间的部分数据，Skill 筛选独立于 Token 的日期、模型与强度筛选。
- 兼容字段 `skills.rows` 保留标准 7/30 天结果，新增 `skills.activity` 保存截至日之前全部可识别历史的精简结构：日期、Skill、来源、仅本快照有效的任务/轮次数字别名。同一天同 Skill 同轮只保留一条，跨日同轮允许分别保留，以便对任意时间窗口正确去重。没有原始会话/轮次 ID、正文、路径或完整参数。
- 可选 `-AsOfDate yyyy-MM-dd` 只用于可复现窗口测试；不传时用当前上海日期。缓存保存精简事件，换日即使全部复用也重新计算窗口。

## 可识别方式与保守边界

直接工具支持 `exec_command`、`shell_command`、`shell` 及其 `functions.` 前缀，从字面量 `cmd` / `command` 读取脚本；支持 shell argv 中 `-c`、`-lc`、`-Command` 的字面量脚本。

`exec` / `functions.exec` 包装器先区分 JavaScript 字符串、注释与代码，再识别直接的 `tools.exec_command` / `tools.shell_command` / `tools.shell` 调用。支持单双引号和没有插值的模板字符串，以及直接置于 `Promise.all` / `Promise.allSettled` 数组中的调用。日志代码从不执行。

Shell 命令以 PowerShell AST 作保守解析，只从内容读取命令的字面量文件操作数取 `SKILL.md`。覆盖 `Get-Content` / `gc` / `cat` / `type`、`head` / `tail` / `more` / `bat`、`sed -n` 以及 `Select-String` / `sls` / `rg` 的内容搜索。单纯 `Get-Item`、`Test-Path`、`ls`、`echo`、`rg --files` 和只输出文件名的搜索不计入。

不会推断动态变量、字符串拼接、模板插值、函数或循环里的调用、复杂条件控制、嵌套 shell、未支持的自定义文件工具、Python/Node 文件 API、Skill provider/MCP 的远程说明读取、压缩摘要/上下文中已有说明的复用，或根本未留下文件读取命令的使用。不能解析的语法保守跳过，因而存在漏计。`SkillDeck` 的完整说明注入口令就可能直接把说明放进会话，没有读取命令；路径口令本身也不计数。

## 来源与隐私

只从文件位置提取 Skill 短名和来源。用户级 skills 为个人，`skills/.system` 为系统，插件缓存布局为插件，工作目录内的 skills 为工作区。未知布局使用 `unknown-` 加截短哈希，不用任意父目录名代替 Skill，避免暴露用户名。命令和路径只在解析时短暂使用，不写入生成数据或缓存事件。

| 来源 | 表示什么 | 典型存储位置（模板） |
| --- | --- | --- |
| 个人 | 用户目录中的 Skill，可由本人编写、安装或复制；不代表一定由本人创作 | `SourceRoot/skills/<Skill>/SKILL.md`，兼容用户目录的 `.agents/skills/<Skill>/SKILL.md` |
| 工作区 | 项目或工作区目录内的 Skill，适合随项目维护 | `<工作区>/.agents/skills/<Skill>/SKILL.md`、`.codex/skills` 或 `skills` 下相同结构 |
| 系统 | 位于 `.system` 的基础 Skill，例如安装/创建 Skill、官方资料查询 | `SourceRoot/skills/.system/<Skill>/SKILL.md` |
| 插件 | 随插件包分发的 Skill，名称增加插件包前缀以区分同名项 | `SourceRoot/plugins/cache/<市场>/<插件>/<版本>/skills/<Skill>/SKILL.md` |
| 未知 | 可识别读取了 SKILL.md，但位置不符合已支持的布局 | 没有统一目录；只输出不透明标识，不猜测所属来源 |

这些是本看板的路径分类，不是 Skill 的作者、信任等级、执行优先级或启用状态。“系统”不表示 Windows 系统文件，“插件缓存存在”也不证明当前已启用。Skill 分类反映被读取路径；当前简介则匹配现在仍能找到的同来源资料。会话统计源仍是 `sessions/` 和 `archived_sessions/`，与 Skill 定义文件目录是两类输入。

页面展示窗口、来源、Skill 标识、当前本地简介、计数和观察提示。API 中的精简活动使用数字别名，供整体任务/轮次去重；不输出原会话 ID、轮次 ID、命令、正文或路径。导出的审计快照只包含筛选后的汇总与当前简介，不含活动记录或数字别名。缓存保留原会话/轮次标识用于去重，但不保存命令/正文；版本 5 清单使用源路径哈希，取代旧版明文路径。生成物与缓存仍被 Git 忽略，不直接编辑。

## 当前本地简介

借鉴 [SkillDeck 固定版本的名称/简介读取](https://github.com/SpaceZephyr/skilldeck/blob/791f365c0e87a13002557a5894dd6ccd81a46d34/server.js#L172-L260)，在原生成器内独立实现受限的 PowerShell 元数据读取，不引入其服务、删除、执行或口令注入接口。读取对象是 `SKILL.md` frontmatter 的 `name`、`description`；文件内容只是数据，不执行其中的指令。

- 历史说明 `skills.metadata` 仍只为 `skills.activity` 已有的来源 + Skill 身份补充资料。当前目录另存 `skills.inventory`，包括限定目录中发现但日志从未识别过的身份；这些条目不加入 activity 或读取计数。不同来源同名不互相补资料；身份一致但当前多处定义不同，标记“简介待确认”，不擅自挑一个版本。
- 默认查找 `SourceRoot/skills`（含 `.system`）、同级 `.agents/skills`、插件缓存的 marketplace/package/version/skills 布局。工作区候选来自 `SourceRoot/config.toml` 的已登记 project 路径及其祖先，只探查 `skills`、`.agents/skills`、`.codex/skills`。不递归遍历工作资料，不通过会话正文找路径，不读取认证文件。UNC 路径、目录/文件软链接与 junction 跳过。
- 只解析头部，最多 16,384 字符；支持普通标量、单双引号、折叠/字面多行简介。不支持完整 YAML 类型、锚点/引用、复杂嵌套或远程 provider。无法解析、超长未闭合、移除、改名、不在限定根或未知来源会出现缺失。名称最多 160 字符、简介最多 2,000 字符；带本机用户名、绝对路径或明显凭证特征的整个字段不输出。前端按文本转义展示，不渲染说明中的 HTML。
- `metadataSchema=1`、`metadataAsOf` 和 `metadata` 与读取活动独立。`metadataAsOf` 是本次实际上海刷新日；历史筛选和测试 `AsOfDate` 不会把当前简介变成历史定义。简介只能说明当前找到的候选资料，不能证明全部安装状态或当时所用版本。
- 元数据缓存 `skill-metadata.json` 使用路径哈希、文件大小/修改时间及脱敏后的名称/简介，不存原路径和 Skill 正文。每次重建限定目录的当前候选索引，仅重读新建/变更的头部，缺失文件移出缓存；不新增 JSONL 读取事件，不改变事件缓存版本/指纹。由历史匹配扩展到当前目录时可直接复用既有元数据缓存，仅首次补读新增条目。解析/脱敏契约未来变化时须升级此独立缓存版本。
- `refresh.skillMetadata` 报告匹配文件数、缓存复用/重读数、底层流读取字节及缓存大小。流缓冲可能读取头部之后少量字节，但不会解析或保存正文；它与 JSONL 的读取量分别统计。

当前英文简介另提供随页面打包的中文释义，源文件为 `web/skill-descriptions.zh-CN.js`。按来源、Skill 标识和原文精确匹配；默认中文阅读，展开保留原文，搜索与导出同时支持两者。英文原文更新后回退原文，不沿用过期释义；没有当前说明的项不编造用途。中文层不修改 Skill 文件、API 原始元数据、统计口径或后台调度，不在刷新时调用模型/翻译接口。

## 当前目录对照与任务组合

`inventorySchema=1`、`inventoryAsOf`、`inventoryScope=known_local_skill_roots` 和 `inventory` 独立记录当前目录发现结果。每个来源 + Skill 一项，`copies` 是同身份下发现的定义文件数。当前文件存在但头部无可展示字段时仍列入目录，状态为 missing；不同说明变体标 ambiguous；相同副本合并并保留份数。文件存在不证明已安装/启用；权限、非标准路径、网络目录及链接等未覆盖情况，使“未找到”不能解读为确定卸载。

默认历史观测模式保持原范围；当前目录模式只选择当前发现身份；对照模式合并当前目录与截至所选日期的历史身份。当前目录日期和历史统计范围分别标注，不能用现在存在的文件推断过去已经安装。目录中新出现但没有历史读数的项只表示没有可识别记录，不是实际使用量为零的证明。卡片、趋势、任务并集和 7/30 天兼容字段继续只由 activity/日志产生。

用途分类由标识与简介的本地关键词规则产生，是查找候选，不是质量或可信度判断；不生成后台模型调用。组合只引用当前有可展示且无冲突说明的身份，预设应优先使用已有总控/流程 Skill。保存只写浏览器 localStorage 的组合名称和来源/标识；加载或快照变化时重新校验，缺失、冲突和旧快照不足以确认当前资料时阻止生成。

任务目标只保留在当前页面，生成的口令是待用户检查的文本草稿，不包含本机路径或 Skill 正文，不自动调用 Skill、启动子进程、发送消息、删除或停用文件。手动复制后由用户选择用于哪个任务；统计不会将草稿生成或复制记为 Skill 读取。组合的浏览器保存不影响源文件或服务数据。

## 总览、筛选与审计使用

总览、趋势、来源分布、明细和导出共用当前 Skill 筛选。整体涉及任务数是筛选后主会话的并集；整体轮次是筛选后轮次的并集，不能把每个 Skill 的任务数或轮次数直接相加。若展示 Skill-轮次记录合计，则同轮读取多个 Skill 分别计数，单独标明单位。每日趋势按日去重；同轮跨日时各日都可能出现，所以每日轮次相加不一定等于全区间去重轮次。

“本期未观测”“本期仅一轮”“同名多处”和“来源待确认”等提示都是复核线索。历史列表只包括曾留下可识别记录的 Skill，不是完整安装清单；当前简介提供限定目录内的候选资料，没有匹配资料不等于确定已卸载，也没有执行成功率、输出质量或不可替代性证据。低频和无记录可能来自缓存复用、未覆盖的读取方式、暂时没有适用任务或已经卸载，不能据此自动删除、停用或合并 Skill。

定期审计时选择明确的自然月或自定义区间，先看活跃范围、任务覆盖和趋势，再用来源/观察项/名称定位需要复核的 Skill。历史观测清单、同名比较及最近观测日期均截至所选结束日，避免把未来才出现的 Skill 当成历史当期的未观测候选。导出当前审计快照，保留日期范围、筛选、生成时间、去重汇总和口径；结合已安装清单、Skill 内容及真实任务效果，决定保留、收窄、按需启用或退役。看板不自动做这些决定，也不创建新的审计计划任务。

## 刷新成本、频率与数据增长

- 现有 Windows 维护任务每分钟检查一次服务和本小时是否已有成功数据；通常每小时实际汇总一次，失败后后续检查重试。页面每 30 秒查询版本，版本变化才重新读取数据；页面筛选本身在浏览器内计算，不扫描 JSONL。
- 正常自动维护、汇总与页面筛选都是本地脚本计算，不调用模型或新增 Codex 会话，不产生 AI Token 开销。
- 每次汇总仍递归枚举所有源文件，查看大小和修改时间；这是元数据检查。未变化的文件读精简事件缓存；新增、变更、迁移路径或缓存失效的文件从头重读。它是文件级增量，不是只读取文件尾部的字节增量。随后从精简事件重新汇总各项指标。
- `refresh.sourceBytes` 是本次枚举到的源文件总大小；`sourceBytesRead` 是本次需重新解析文件在枚举时的体积之和，不是精确的物理磁盘 I/O 计数。`cacheBytesRead` 记录本次读取的缓存文件体积，`cacheBytes` 是当前清单引用的有效缓存体积；`elapsedMs` 是生成阶段耗时，不包含互斥等待及浏览器加载。
- 校验与按源顺序合并使用 PowerShell 内置 `Add-Type` 编译的内存辅助代码，保留结构字段投影、数值/身份/时间校验、响应匹配和历史去重。常见字符串事件使用长度编码的身份键，数字等少见类型回退原 JSON 身份规则，避免分隔符碰撞或类型丢失；不改变提取指纹或事件缓存版本。
- 未变源的历史写入复用同时绑定数据源、解析指纹、文件路径哈希、文件签名、已读取的缓存文本哈希及历史块哈希。没有绑定的旧清单正常读取，首次刷新补齐绑定；缓存内容改变、重解析、历史块缺失或完整性失效时重新生成当前源的不可变历史块。原日志已缺失的历史仍每轮完整校验，损坏时继续拒绝新快照。
- 所有来源完成响应匹配后，排序前释放已证明被消耗记录覆盖的额外逐请求记录，每线程保留首条以保持分组和数字别名；缺少明确响应匹配的旧记录不裁剪，继续参与原补计判断。同时清空临时身份索引和上一份 JSON 引用，并回收临时内存。原缓存和历史块不裁剪。
- `refresh.historyWritesReused` 是本轮避免重新序列化的当前源历史块数，不代表跳过历史完整性检查。`refresh.coveredRecordsReleased` 是上述释放的记录数。`refresh.phaseMs` 分别记录枚举/初始化、当前事件、留存历史、内存整理（`workingMemory`）、Token/任务汇总、Skill 汇总、元数据及准备输出的毫秒耗时；不包含随后 JSON 序列化、磁盘提交、互斥等待或浏览器加载。它们是可选诊断字段，旧数据仍可显示。
- 缓存按源路径一份覆盖，HTML、数据 JSON 和清单原位原子替换，不会每刷新一次新增完整快照。精简活动也随同一份数据 JSON 覆盖。只有手动点击导出时才另存审计快照。
- 原始 Codex 日志随 Codex 使用自行增长；仪表盘不会复制整套日志。源文件移动、归档或删除可能遗留旧路径缓存；现有服务日志也会追加。当前没有孤立缓存自动清理或日志轮转，因此不能承诺体积永不增长。
- 精简事件另保存在按数据源隔离的 `.codex-usage-dashboard-history/`，源 JSONL 迁移后仍可复用其中的 Token、请求、压缩与 Skill 说明读取事件；指标窗口与去重定义不变。历史与加速缓存分开，不包含会话正文；原日志缺失时应保留该私有历史目录。旧孤立缓存需由显式恢复入口确认来源及兼容性，不能自动混入切换后的数据源。历史恢复范围不等于安装清单，也不证明迁移前全部记录完整。
- 当前事件缓存版本为 7，按读取函数指纹复用，汇总或界面修改不触发全量重读。v5 缺少实际线程归属，v6 缺少逐请求消耗，均从只读日志重建，不热迁移或接受其旧指纹。读取函数逻辑、缓存格式、身份/模型归属或消耗事件提取改变时仍须重建；当前相同版本及相同读取函数的精简事件才能复用。

## 验证入口

`tests/Test-Generator.ps1` 继续验证原 Token/请求统计，并使用独立合成 Skill 日志验证清单为零、真实读取、轮次/归档去重、来源、代理排除、损坏行、上海日期边界、冷暖缓存和跨日重算。运行 PowerShell 5.1 与 7 两套。

`tests/Test-TokenAttribution.ps1` 验证实际线程及模型/范围归属；`tests/Test-TokenFallback.ps1` 验证缺失消耗补计、响应与副本去重、轮次/累计重置边界、坏来源字段及缓存恢复，两项也运行 PowerShell 5.1 与 7 两套。

`tests/Test-RefreshPerformance.ps1` 使用合成数据验证身份键与原 JSON 的等价关系、来源顺序/响应匹配、被覆盖记录释放时的分组与旧补计记录保留、旧绑定升级、未变历史复用、合法缓存变化后的留存、未知正文属性剔除，以及有/无原日志时的历史损坏保护。两种 PowerShell 均运行；不使用随机器负载波动的耗时阈值。性能比较应冻结相同输入，另行记录实际耗时及统计结果一致性。

`tests/Test-Frontend.cjs` 验证双窗口计数、来源、转义、筛选隔离、tab 保留、空数据/旧快照、无效数据不替换上一版。`tests/Test-Service.ps1` 覆盖服务提交与刷新失败保护；`tests/Test-UiContract.ps1` 同时检查源和已生成页面契约（`-SourceOnly` 仅检查源）。可选 `tests/Test-Browser.cjs` 使用已安装的 Playwright 与 Edge，核对桌面/390px 布局、API 与表格一致及刷新保留；`--playwright` 可指定本机包路径，`--refresh` 会通过现有页面触发一次本地刷新。
